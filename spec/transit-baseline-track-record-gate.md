# Transit Baseline Track-Record Gate

The transit baseline track-record gate is a checked read surface over the weather-transit-delay forward-run corpus. It reports the baseline-first performance evidence that exists today while preserving the sample-size boundary for quality and calibration claims.

The fixture is generated by:

```bash
python3 scripts/ope.py transit-track-record-gate
```

The gate reads the checked corpus from `spec/fixtures/generated/transit-forward-run-corpus/`. It does not execute forward runs, resolve outcomes, create scoring records, fetch live data, read ignored `.ope/live/` captures, or store credentials.

## Current Fixture

The checked gate currently reports:

- one resolved comparable scored public transport forward run
- six excluded corpus rows
- Brier score `0.4489`
- baseline Brier score `0.5625`
- baseline lift `0.1136`
- one comparable horizon window and six excluded windows

This is implementation evidence only. The gate keeps `trackRecordStatus` and `calibrationStatus` at `not_enough_resolved_comparable_outcomes`.

## Thresholds

The corpus policy declares:

- at least 30 comparable resolved runs before baseline track-record claims are allowed
- at least 100 comparable resolved runs before calibration summaries are generated

Below the calibration threshold, `calibrationGate.summaryGenerated` is `false` and `calibrationGate.calibrationSummary` is `null`. One scored forward run must never be treated as calibration evidence.

## Claim Boundary

The gate keeps all of the following false until thresholds are met:

- `qualityClaimAllowed`
- `baselineTrackRecordAllowed`
- `calibrationClaimAllowed`
- `oneOffForwardRunCanCreateCalibrationEvidence`

Normal checks stay offline, and local live captures remain ignored local artifacts rather than committed calibration or track-record evidence.
